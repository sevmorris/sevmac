Daily Operations

This card shows the commands I use each day. It does not tell you how the tools operate. For that information, read SMAC-1.

The card describes one machine: mine. The commands come from mrk, which is a personal setup. The tools are general, but the packages, login items and preferences they manage are personal choices. Change those lists before you run a command on a different machine. See SMAC-1, Section 1.

Each part of this page starts with a moment: you install a package, a week goes by, or a problem occurs. Find the moment. Then run the command.

A

The Card

six commands

These are the commands to use most days. Each one is a script in ~/bin or a shell function in ~/.aliases. You can run each one from any directory.

status Opens the health dashboard. Press f for a fix. Press r to refresh.
mrk-menu Opens the command launcher. Use it when you do not remember a command.
sync -c Adds new installed packages to the Brewfile. Then it commits the change.
snapshot-prefs Exports the application preferences. Then it pushes them to mrk-prefs.
pushall Pushes each repository in ~/Projects. Then it syncs ~/mrk.
update Runs topgrade. It upgrades the packages. It does not close the applications.
Rule — When You Do Not Remember
Run mrk-menu. It shows all the mrk commands in groups. Select a command to run it. You do not need to remember the flags.
B

Automatic Tasks

no action necessary

The system does these tasks for you. Do not put them in a manual routine.

Table B-1. Scheduled Tasks
TaskScheduleWhat It Does
clear-app-caches Each day at 03:00, and at load Clears the cache directories of the usual applications. A LaunchAgent starts it.
clear-derived-data Each Sunday at 03:00 Clears the Xcode DerivedData directory. A LaunchAgent starts it.
check-updates Each 7 days, at shell start Compares ~/mrk to the remote. It is silent if there are no updates.

You can also run clear-app-caches or clear-derived-data manually. This is not usually necessary. Run clear-derived-data manually if a build fails and you think the cause is a stale build product.

Note — After check-updates Reports an Update
Run make -C ~/mrk pull to get the update. This command is a fast-forward pull. It does not change your local work.
C

After You Change Something

the important part

The system does not find your changes. You must record them. Each row below shows an action and the command that records it.

Table C-1. Change and Command
You did thisRun thisWhy
You installed a package with Homebrew. sync -c Adds the package to the Brewfile. A package that is not in the Brewfile is not installed on a new machine.
You changed the settings of an application. snapshot-prefs Exports the plist and pushes it to mrk-prefs. See Table 2.4-1 in SMAC-1 for the managed applications.
You added or removed a login item. sync-login-items -c Updates the tracked list in scripts/post-install.
You removed a package with Homebrew. sync -p Removes the Brewfile entry for the package.
You changed a file in ~/mrk. mrk-push "message" Commits and pushes the change. It also prunes the old Pages deployments.
You made commits in a project. pushall Pushes each repository in ~/Projects. Then it syncs ~/mrk.
Note — The pushall Secret Scan
The pushall command examines each file before it makes a commit. If it finds a possible secret, it stops for that repository and continues with the others. It leaves the changes staged, so git diff --cached shows you what it stopped. The command stages only the tracked files. It never adds an untracked file. Use pushall --dry-run to run the scan and change nothing.
Rule — The Only Rule That Is Important
If you install it with Homebrew, run sync -c. If you configure it in a window, run snapshot-prefs. A change that you do not record does not move to the next machine.

Neither command records a key. mrk-prefs never carries private key material, so ~/.ssh, ~/.gnupg and your signing identities move only through snapshot-keys. That is a migration step, not a daily one — see SMAC-1, Section 2.6.

Do not run sync after each installation. Once each week is sufficient. But always run it before a migration. See the checklist in SMAC-1, Section 2.6.

Note — To Keep a Package but Hide It from sync
Put the formula or cask name in ~/.mrk/sync-ignore. Use one name for each line. The sync command then does not suggest it. The file does not exist until you make it.
D

Each Week, Each Month

the short routine

Each week. These three commands take a few minutes.

update        # Upgrade all the packages with topgrade
sync -c       # Add new packages to the Brewfile, then commit
pushall       # Push all the project repos, then sync ~/mrk

The update command is a shell function in ~/.aliases. It runs topgrade and nothing more. It does not close the applications. It does not offer a reboot.

Each month. Start with update-full. Then do three more steps.

Caution — update-full Closes Your Applications
The update-full command closes all the running applications. It tells each application to save its open documents first. It keeps your terminal open only if the terminal is iTerm2, Terminal, Warp, or Ghostty. If the terminal is a different one, the command gives a warning first. Stop your work before you run this command. The command asks for confirmation before it starts. It stops with an error if there is no terminal, unless you give the --yes option.

  1. Run the full update. This one command does all of these steps in sequence: it pulls ~/mrk, closes the applications, runs the macOS software updates, runs topgrade, builds the mrk Go tools again, removes the .DS_Store files, and runs brew doctor. Then it offers a reboot.

    update-full              # Ask before the start, offer a reboot at the end
update-full --no-reboot  # Do not offer a reboot

  2. Export the application preferences. Do this after you change the settings of any application.

    snapshot-prefs

  3. Open Magic Backup Machine. Run a backup to the local destination and the external destination. This backup copies the files that mrk does not manage. These files include the Logic Pro projects, the audio presets, and the browser profiles. See SMAC-1, Section 4.1.

  4. Open the health dashboard. Look for a ⚠ or an ✗ indicator. Press f to get a suggested fix.

    status
Note — To Remove the .DS_Store Files Only
Step 1 includes the clean-ds command. You can also run it alone. Use clean-ds --dry-run to see the files first. The command removes the .DS_Store files from the local disk only. It does not touch ~/Library, ~/Desktop, the network volumes, or the external volumes.
Note — Two Spellings, One Command
The update-full and update --full commands do the same thing. The update function sends --full to update-full. It sends all the other arguments to topgrade.
Note — Housekeeping
The maintain command prunes the Pages deployments, fetches with --prune, validates the scripts, and checks the builds. Run it when you work on mrk itself. Use maintain --dry-run to see the changes first.
E

If Something Is Wrong

four steps

Do these steps in this sequence. Stop when the problem is corrected.

  1. Open the dashboard. It shows eight panels, and a ninth when a backup exists. Find the check that is not ✓. Press f to get a suggested fix. The tool asks for confirmation before it makes the change.

    status

  2. If a command is not found, the ~/bin directory is possibly not on the PATH. Correct it, then start a new shell.

    doctor --fix
exec zsh

  3. If a TUI does not draw correctly, build the binaries again. This applies to status, mrk-menu, and the sync picker.

    make -C ~/mrk build-tools

  4. Read the log. The setup, brew, and post-install phases write to it.

    tail -50 ~/.mrk/install.log

If the problem continues, find it in the troubleshooting table in SMAC-1, Section 2.9.

Caution — To Undo the macOS Defaults
The rollback script removes all the defaults write changes that mrk applied. Read the script before you run it.
bash ~/.mrk/defaults-rollback.sh
